# 利用者マニュアル — 在庫管理システム (Workers + D1 版)

日常的に在庫を扱う人向けの手順書です。管理者向けの内容（ユーザー管理・
権限変更・バックアップ）は [管理者ガイド](admin-guide.md) を参照してください。

## ログインとログアウト

- アプリ (`/app`) を開き、「Google でログイン」から Google アカウントで
  ログインします。多要素認証（Face ID / パスキー）は Google アカウント側の
  設定に従います。アプリ独自のパスワードはありません。
- ログイン状態（セッション）は 8 時間有効です。期限が切れたら再度ログイン
  してください。
- ログアウトは画面右上の「ログアウト」ボタンから行います。
- ログインできても「権限が付与されていません」と表示される場合は、まだ
  ロールが割り当てられていません。管理者にロール付与を依頼してください。
- 表示されるメニューは、自分のロールに付与された権限によって変わります。
  できない操作はメニュー自体が出ません（サーバー側でも 403 になります）。

画面上部の「リアルタイム接続中」の表示は、在庫変更を自動で画面へ反映する
接続の状態です。切断されても業務はできますが、表示が古い可能性があるため、
必要に応じて再読み込みしてください（再接続時に自動で最新化されます）。

## ダッシュボード

ログイン直後の画面です。アラートの総数と内訳（期限切れ / 期限接近 /
在庫不足 / マイナス在庫）、在庫レコード数と総数量、期限が近い在庫
（最大 5 件）が表示されます。棚卸しが実施中・差異承認待ちの間は、
その旨のバナーが出ます（この間は入庫・消費・移動ができません）。

## 在庫の見方（在庫一覧）

- キーワード（SKU / 商品名 / ロット番号）、倉庫、保管場所で絞り込めます。
- 有効期限は色で示されます: 期限切れは赤、期限が近いもの（商品ごとに
  設定されたアラート日数以内、未設定なら 30 日以内）は黄で表示されます。
- 数量がマイナスの在庫は赤字で表示されます（承認済みの例外消費の結果です）。
- 「CSV ダウンロード」で、表示対象（自分の倉庫スコープ内）の在庫一覧を
  CSV で保存できます。

## 入庫

1. メニュー「入庫」を開きます。
2. 商品、保管場所、ロット番号、数量を入力します。
3. 期限管理対象の商品は有効期限が必須です。「この商品は有効期限が必須です」
   と表示されたら期限を入力してください。
4. 「入庫を登録」を押すと、在庫ID と現在数量が表示されます。

同じ商品・同じロットの在庫が既にある保管場所へ入庫すると、その在庫へ
加算されます。二重送信しても二重に加算されない仕組み（冪等性）になっています。

## 消費

1. メニュー「消費」を開きます。
2. 商品、数量、部署、用途を入力します（部署・用途は必須で、履歴に残ります）。
3. 保管場所は任意です。指定しない場合は、アクセスできる全場所から引きます。
4. 「消費を登録」を押すと、FEFO（期限の早いロットから）のルールで
   どのロット・保管場所から何個引かれたかが表で表示されます。
   期限切れのロットは原則として引かれません。
5. 在庫が足りない場合はエラー (409) になり、何も引かれません。
   あらかじめ承認されたマイナス在庫申請を使う場合は、「マイナス在庫承認 ID」
   に申請の ID を入力してください（下記「マイナス在庫」参照）。

## 移動

1. メニュー「移動」を開きます。
2. 商品、移動元・移動先の保管場所、数量を入力します。
3. ロットは任意です。指定しない場合は消費と同じ FEFO 順に引きます。
4. 「移動を登録」を押すと、ロットごとの移動元・移動先の在庫ID と数量が
   表示されます。移動元・移動先の両方の倉庫へアクセスできる権限が必要です。

## 履歴

入庫・消費・移動・調整（棚卸しの差異反映）の記録を新しい順に表示します。
種別、数量の変化、数量の前後、部署 / 用途が確認できます。
自分がアクセスできる倉庫の分だけが表示されます。

## マイナス在庫（例外申請と承認）

在庫が足りないのに消費しなければならない場合の例外フローです。

### 申請する人（`negative.request` 権限）

1. メニュー「マイナス在庫」を開きます。
2. 対象の在庫、許容数量、理由（必須）を入力して「申請する」を押します。

### 承認する人（`negative.decide` 権限）

1. 同じ画面の申請一覧で、承認待ちの申請を確認します。
2. 「承認」または「却下」を押します。**自分の申請は自分で承認できません**
   （ボタンが出ず、API でも 422 で拒否されます）。

### 承認されたら

消費の際に「マイナス在庫承認 ID」へ申請 ID を指定すると、承認された
数量の範囲で在庫がマイナスになる消費ができます。承認は 1 回使うと
使用済みになります。マイナスになった在庫はアラートに表示されます。

## 棚卸し

棚卸しの実施中と差異承認待ちの間は、**入庫・消費・移動がすべて停止**します
（画面にもバナーが出ます）。計画的に実施してください。

1. メニュー「棚卸し」を開き、「棚卸しを開始する」を押します
   （`stocktakes.manage` 権限が必要）。この時点の帳簿数が記録されます。
2. 明細表で各在庫の実数（実際に数えた数量）を入力し、行ごとに「保存」を
   押します。実数を入力しなかった行は「帳簿どおり（差異なし）」として
   扱われます。
3. 「棚卸しを終了する」を押します。
   - 差異が無ければそのまま確定し、在庫更新が再開されます。
   - 差異があれば「差異承認待ち」になります（停止は継続します）。
4. 差異承認待ちでは、内容を確認してから次のどちらかを選びます。
   - 「承認して在庫へ反映」: 差異が調整として在庫に反映され、確定します。
   - 「差し戻す」: 実数入力の状態に戻ります（入力した実数は保持されます）。

## アラートの見方

メニュー「アラート」に種類別に表示されます。

| 種別 | 意味 |
|---|---|
| 期限切れ | 有効期限を過ぎた在庫がある |
| 期限接近 | 商品に設定されたアラート日数以内に期限が来る |
| 在庫不足 | 数量が安全在庫以下になっている |
| マイナス在庫 | 承認済みの例外消費で数量がマイナスになっている |

## よくあるエラー

| 表示・状態 | 意味と対処 |
|---|---|
| 401 / ログイン画面に戻る | 未ログイン、またはセッションの期限切れ（8 時間）です。再度ログインしてください |
| 403 | その操作の権限が無い、または対象倉庫が自分の担当範囲外です。必要な場合は管理者に権限・担当倉庫の付与を依頼してください。「権限が付与されていません」はロール自体が未割当です |
| 409 在庫不足 (INSUFFICIENT_STOCK) | 在庫が足りず、消費・移動は実行されませんでした。在庫を確認するか、マイナス在庫の例外申請を使ってください |
| 409 競合 (STOCK_CONFLICT) | 他の操作と競合しました。画面を再読み込みしてからもう一度操作してください |
| 422 | 入力は正しい形式でも業務ルールに反しています（自分のマイナス在庫申請を自分で承認しようとした、同じ冪等キーで違う内容を送った、など）。メッセージを確認してください |
| 423 棚卸し実施中 | 棚卸しが終わるまで在庫更新は停止しています。棚卸しの完了（差異がある場合は承認まで）を待ってください |
| 404 | 対象が存在しない、または自分の担当範囲外のため表示されません |

## 注意点

- 数量は整数のみです。小数点のある数量は扱えません。
- 画面の自動更新はベストエフォートです（切断中の変更は届きません）。
  重要な判断の前には再読み込みして最新化してください。
- マスタ（商品・倉庫・保管場所・ロット）の登録・編集は「マスタ管理」画面で
  行います（`master.write` 権限が必要）。編集は各行の「編集」ボタンから
  フォームが開きます。削除は論理削除で、在庫や履歴には影響しません。
